# 밸런싱 판단 기준

> 🔴 **이 문서에는 규칙만 적는다. 수치는 적지 않는다.**
> 현재 값 = 에셋(`Assets/Data/**`, `MainSkillTree.asset`, `BalanceConstants.cs`) · 목표 수치 = `Tools/BotPlaytest/targets.json` · 측정 결과 = 보고서(`BotRuns/report/`).
> 사본을 두면 한쪽만 낡는다(CLAUDE.md §7).

## 1. 목표 — 사용자가 정한 것

| # | 목표 | 어떻게 재나 |
|---|---|---|
| G1 | **4~5시간** 안에 전 노드 해금 + 우주 어려움 클리어 | 정주행(campaign)의 추정 플레이 시간 = 게임 시간 + 선택 1회·판 사이 여유(`targets.json`) |
| G2 | 난이도 서열 **농장1 < 농장2 ≤ 해변1 < 해변2 ≤ 우주1 < 농장3 ≤ 우주2 < 해변3 < 우주3** | 고정 기준 트리(probe)에서 잰 난이도 점수 D의 인접 관계 8개 |
| G3 | 목표마다 **클리어까지 평균 판수가 비슷** (그래서 뒤로 갈수록 판 길이만 길어진다) | 목표별 평균 판수의 변동계수 |
| G4 | **전 노드 해금 시 우주 어려움을 안정적으로** 클리어 | 풀트리 우주3 클리어율, 캐릭터마다 |
| G5 | **스킬 간 밸런스** — 같을 필요는 없고 장단점이 있어야 한다 | `SKILL_AXES.md` |
| G6 | **캐릭터 간 밸런스** | 같은 목표·트리에서 캐릭터별 D 차이 |
| C1 | 🔴 **쿨타임 15초 초과 스킬 금지** (하드 제약) | 쿨 감사표(`cooldowns.json`) — 맨몸 쿨, 모든 레벨·진화 단계 |
| C2 | **진화하면 쿨이 길어진다** (원칙) | 진화 단계 Lv1 쿨 > 직전 단계 Lv10 쿨. 강한 진화부터 맞춘다 |

- 목표 우선순위: **C1 → G4 → G2 → G5 → G6 → G3 → G1.** 이터레이션마다 기준에서 가장 먼 것 하나를 겨냥한다.
- 허용폭(`<`·`≤`의 D 차이, CV 상한, 80% 등)은 Claude가 제안하고 **사용자가 확인했다(2026-09-18)**. 바꿀 땐 `targets.json`만 고친다.
- ⚠️ 봇은 무작위로 골라 사람보다 약하다. 봇 기준 4~5시간이면 사람은 더 빨리 끝난다.

## 1-B. 사용자 설계 의도 — 수치를 고를 때 방향을 정하는 기준

지표가 "어디가 틀렸나"를 말한다면 이 절은 "어느 쪽으로 고쳐야 이 게임답나"를 말한다. **이 의도와 반대 방향의 변경은 지표가 좋아져도 하지 않는다.**
- **맵은 정체성이 있어야 한다** — 다른 맵의 스테이지를 복사한 느낌이면 실패다. 우주 = 비행선(쏟아지는 비행선 벽 포함).
- **비행선 = 단일 대상 딜·대공 딜을 시험하는 몹.** 체력·피해가 높고, 터지면 여러 종류가 쏟아진다(그 스테이지 세기로).
  쏟아지는 것 자체는 큰 압박이 아니지만 **캐릭터 코앞에서 터지면 순식간에 큰 피해** — 그게 긴장이다. 하늘을 나는 배라 높이가 제각각이다.
- **군중제어 저항: 보스는 아주 강하게, 비행선은 적당히 강하게.** 넉백·기절로 보스전을 무력화할 수 있으면 안 된다.
- **근거리 공격은 "한 방이 크고 쿨이 긴" 쪽**이다(짧은 쿨로 계속 밀어내는 것 아님).
- **진화하면 쿨이 길어진다**(C2) · **쿨 15초 초과 금지**(C1).
- **QWER를 다 누르고 있으면 네 스킬이 전부 돌아야 한다** — 한 스킬이 발동 기회를 독점하는 빌드는 버그로 본다(발동 순서 = 오래 기다린 스킬 먼저).
- **공중을 쫓는 스킬(회오리 R0 본체 등)도 화면 위로 잘려 보이면 안 된다.**

## 2. 손잡이 — 어디를 만질 수 있나

축별 위치·효과 범위·주의점은 **`KNOBS.md`**. 요약:
- **A 맵** — 적이 얼마나 센가(`StageTable_*`, `EnemyDef_*`, `AscensionTable`, `ScalingTable`)
- **B 스킬 파워** — 빌드가 얼마나 센가(`Prog_*`, `Evo_*`, `Passive_*`, 기본 개수 상수)
- **C 스킬트리 파워** — 메타 진행이 얼마나 세지는가(`MainSkillTree.asset` 노드 효과·가격대)
- **D 경제·진행 속도** — 얼마나 빨리 강해지는가(노드 가격 곡선, 정수 드랍, XP 곡선)
- **E 캐릭터** — 캐릭터끼리 공평한가(`Char_*`, 시작 스킬 파워)

## 3. 🔴 손잡이 고르는 규칙 — 매번 분석을 남긴다

증상 하나를 골랐으면 **축 A~E 각각에 "이 축이 원인이라는 증거"를 데이터로 적고 1~5점을 매긴 뒤** 고른다.
결과는 이터레이션 파일의 `axisAnalysis`·`chosenAxis`·`rejected`에 남기고, 보고서에 그대로 뜬다.

| 축 | 이 축을 고를 증거 | 아니라는 신호 |
|---|---|---|
| A 맵 | 사망·피격이 **특정 스테이지·특정 적**에 몰림(이웃 대비 급등), 캐릭터·빌드와 무관하게 같은 곳, 같은 트리의 다른 맵엔 없음 | 빌드·캐릭터에 따라 크게 갈림 / 곡선 전체가 고르게 어려움 |
| B 스킬 | 파워·축 프로필 이상치, 특정 스킬·루트 보유 여부로 진행률이 크게 갈림, C2 위반 | 모든 빌드가 같은 지점에서 막힘 |
| C 트리 | 트리 비율에 따른 D 기울기가 틀림(초반은 맞는데 풀트리 G4 실패 등), 특정 노드 구매 직후 급변 | 트리와 무관하게 같은 결과 |
| D 경제 | 서열(G2)은 맞는데 시간(G1)·판수(G3)만 어긋남 | 서열 자체가 틀림 |
| E 캐릭터 | 같은 조건에서 캐릭터 간 D 차이, 시작 스킬 프로필 이상치 | 차이가 노이즈 폭 안 |

- 🔴 **"어려우니 맵 너프"를 기본값으로 쓰지 않는다.** A는 증거가 스테이지·적 단위로 국소화될 때만. 곡선 전체가 어려우면 B·C·D 중 무엇이 모자란지부터 가린다.
- **부작용 범위를 같이 적는다.** 맵 = 그 맵만 · 스킬 = 그 스킬을 쓰는 모든 판 · 트리·경제 = 전 목표 + G1 시간.
- **`AscensionTable`은 세 맵 공통**이라 맵 사이 서열(G2) 조정엔 맞지 않는다 — 맵별 `StageTable_*`을 먼저 본다.
- **진화 스킬이 강하다는 결론이면 쿨타임(`Evo_*.baseCooldown` → 필요하면 `Evo_*.levels`의 쿨 스텝)을 먼저 올린다.** 쿨로 안 되면 피해. 변경 뒤 C1(15초)을 넘으면 그 변경은 무효.
- **한 번에 가설 하나, 손잡이 1~3곳.** 원인이 섞이면 다음 루프에서 판정할 수 없다.
- **게임 로직 코드는 루프에서 고치지 않는다.** 데이터 칸으로 부족하면 `codeSuggestions`에 제안만 쓴다(사람이 결정).

## 4. 판정 — 가설이 맞았나

- 이터레이션 파일의 `prediction`(지표·방향·예상 크기)과 `passCriterion`을 다음 세션 결과와 대조한다.
- **노이즈 폭**: 같은 조건의 캠페인 간 표준편차(보고서의 `attemptsStd`·G1 `spread`). 변화가 그 안이면 `inconclusive`.
- `confirmed` / `refuted` / `inconclusive` 중 하나 + `verdictNote`(숫자 근거).
- **반박됐고 지표가 반대로 움직였으면 되돌리는 것부터 검토**한다. 되돌려도 그 이터레이션은 "변경 포함"이다(되돌리기 + 다음 가설).

## 6. 이미 알려진 측정 한계

- **봇의 선택 정책은 사람과 다르다** — 레벨업은 "2차 열쇠 → 1차 열쇠 → 보유 스킬 레벨업 → 아무거나", 진화는 열쇠로 필요한 것 우선(`BotPilot` 머리 주석).
  열쇠를 우선하는 건 **2차 진화 표본을 만들기 위해서**다. 그래도 조합별 표본은 적으니 판정 전에 `n`을 본다. 스킬 하나만 재는 시험장(gym)은 미구현.
- **봇 정책을 바꾸면 그 앞뒤 측정은 비교하지 않는다** — 보고서의 이터레이션 비교는 같은 정책 구간 안에서만 한다.
- 스킬 상태는 **판 종료 시점**으로 집계한다 — 판 중간에 진화하면 진화 전 기여가 진화체에 섞인다.
- 쿨 감사는 `EvolveSkill`·`TryUseSkill`의 일부를 흉내 낸다 → 실제 판의 `skills[].baseCdLast`와 어긋나면 감사 코드를 먼저 의심한다.
- GDD·스킬 설명과 코드가 다른 곳(예: 산탄 "버프", 오브·제우스 "끌어당김")은 **코드대로 측정**한다. 어느 쪽이 의도인지는 사람이 정한다.
